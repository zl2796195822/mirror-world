# EXP-3D-002 场景分块与空间串流报告 (Scene Streaming Report)

本文件记录在 300m × 300m 复杂青禾街区中实施的 **空间分区 (Scene Chunking)** 与 **距离感应懒加载 (Spatial Streaming)** 的实验结论。

---

## 1. 分区架构规划 (Zone Hierarchy)

为了避免客户端首屏一次性下载并实例化全街区资产，场景划分为三个物理与视觉独立的地理区域：

```text
       [ North: Zone B · 商务办公与北公寓 ]
                     │  (z < 5m 触发加载)
                     ▼
       [ Center: Zone A · 商业十字路口与出生区 ] (青禾咖啡 / 拾光便利店 / 楼梯斜坡)
                     ▲
                     │  (z > 15m 触发加载)
       [ South: Zone C · 社区公园与公交站 ]
```

| 分区标识 | 范围与包含地标 | 加载策略 | 几何体与构件 |
|---|---|---|---|
| **Zone A (核心区)** | 中心十字路口、青禾咖啡、拾光便利店、台阶、斜坡、窄巷 | **首屏必载 (出生点)** | 咖啡店落地玻璃、门头招牌、台阶刚体、斜坡刚体、雨棚 |
| **Zone B (北区)** | 北侧干道、六层商务办公楼、青禾公寓1号楼、北侧住宅群 | **向北移动按需加载** (`z < 5m`) | 玻璃幕墙大厦、高层住宅抹灰外墙、窗框与独立碰撞体 |
| **Zone C (南区)** | 南侧干道、青禾路公交站、小公园绿化、南侧住宅楼 | **向南移动按需加载** (`z > 15m`) | 公交候车棚、LED屏、公园草坪路径、长椅构件 |

---

## 2. 首屏载入与串流时间实测 (Streaming Benchmarks)

基于本地构建产物测量（模拟静态 CDN 资源分发）：

- **初始静态代码体积 (Initial JS)**：`1,232.03 kB` (Gzip 压缩)
- **初始纹理资产 (Initial Textures)**：`1.05 MB` (10 张 PBR 贴图全部加载)
- **首屏可交互时间 (Time to First Meaningful Scene)**：**423ms ~ 571ms**（桌面环境 loopback 测得）
- **内存表现**：
  - 仅 Zone A 活跃时基线内存：约 **43.7 MB**
  - Zone A + Zone C 共同挂载时：约 **52.2 MB ~ 83.8 MB**
  - 三个 Zone 全量就绪时：约 **120.3 MB**

---

## 3. 距离滞后阈值与抗颠簸机制 (Hysteresis)

在漫游过程中，若玩家在分区边界反复横跳，频繁卸载与重新挂载组件会导致严重的 GC 停顿与网格重建开销。
为此，本实验采用了**空间滞后缓冲（Distance Hysteresis）**：
- **触发加载距离**：北向进入 `z < 5m` 挂载 Zone B；南向进入 `z > 15m` 挂载 Zone C。
- **卸载保护区**：离开边界需超出额外 **20 米** 以上才触发卸载，避免高频挂载/卸载抖动。

---

## 4. M7 推荐的场景串流方案

1. **不能一次性加载全场景**：青禾街区最终将包含更多街巷、店铺内饰与精细道具，首屏必须采用分块按需加载。
2. **推荐方案**：采用 **glTF / glb 按区切片 + 空间九宫格调度（3x3 Grid Chunking）**。
3. **后台 Worker 预加载**：利用 Web Worker 异步 fetch 与 parse glTF 缓冲区，主线程只负责挂载进入场景图，避免解析卡顿。
