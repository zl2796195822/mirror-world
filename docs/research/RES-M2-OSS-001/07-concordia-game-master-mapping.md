# 07 - Concordia Game Master 与镜界 World Kernel 逐项深度对照 (Game Master Mapping)

在多智能体社会模拟架构中，Google DeepMind 的 **Concordia Game Master (GM)** 与镜界的 **World Kernel** 在顶层职责上都扮演着“中介仲裁者（Mediator / Arbiter）”的角色——即打破传统游戏或多 Agent 系统中“Agent 可以直接修改共享状态”的混乱模式，强制实行“行动必须经由权威裁决”。

然而，二者在底层哲学、技术选型、权威来源与系统目标上存在**根本性分歧**。严禁在架构文档中笼统使用“二者类似”一笔带过。以下围绕 9 个核心架构维度展开逐项深度剖析与映射。

---

## 逐项对比与架构映射表

| 对照维度                             | Concordia Game Master (`concordia.environment.engine`)                                                                                                                                               | 镜界 World Kernel (`@mirror/world-kernel`)                                                                                                                                   | 架构机理差异深度剖析                                                                                                                                                  | 镜界关键结论与吸收边界                                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **1. Authority (权威性来源)**        | **LLM Semantic Authority (大模型语义权威)**<br>GM 本质是一个基于思维链提示词的 Prompt 包装器。它根据人类对情境的自然语言描述，由大模型决定“下一步合理的结果是什么”。                                 | **Deterministic Code Authority (确定性代码与数据权威)**<br>Kernel 是一套用 TypeScript 严格编写的规则引擎与状态机，由 PostgreSQL 约束与行级锁共同赋予权威。                   | Concordia 的权威建立在 LLM 的常识推理上；镜界的权威建立在数字社会物理守恒与经济记账上。在镜界中，数字世界事实必须有绝对不可推翻的法律效力，不能因 Prompt 波动而漂移。 | **REJECT EXTERNAL**: 绝对不把世界权威托付给大语言模型。<br>**KEEP**: 坚持 Kernel 代码与数据库为唯一权威写入口。 |
| **2. Determinism (确定性)**          | **Non-Deterministic (完全非确定性)**<br>依赖模型采样概率（Temperature / Top-P）。相同的输入在不同时间、不同并发批次下必然产生不同的叙事。                                                            | **Deterministic (确定性)**<br>所有条件判断（权限、距离、金额）必须是确定性布尔值。随机行为严格依赖显式注入的固定 Seed。                                                      | Concordia 面向的是单次发散型的社会学与心理学观察；镜界是长期持续运营的数字社会，必须保证无论回放多少次，同一时刻的账本与状态绝对一致。                                | **KEEP**: 坚决排除任何未注种子的非确定性因子。                                                                  |
| **3. Validation (前置条件校验)**     | **Narrative Context Checking (叙事合理性裁决)**<br>GM 在 `EventResolution` 中读取所有挂载组件的文本表示，由 LLM 判断例如“某人是否真有钥匙”。若 Prompt 遗漏细节，极易产生逻辑幻觉（如凭空变出物品）。 | **Multi-Stage Guard (强类型多阶段守门)**<br>1. `@mirror/contracts` 格式与数值边界拦截；<br>2. Kernel Validator 严格按顺序校验：状态、时间、版本、空间连通性、背包、余额。    | 镜界的前置校验是硬约束。无论 Agent 多么善于言辞，如果数据库中余额少 1 分钱，Kernel 立即返回 `KERNEL_INSUFFICIENT_FUNDS`，绝无幻觉越界可能。                           | **KEEP**: 保持纯函数形式的分步断言式校验，防范漏洞。                                                            |
| **4. Commit (提交与落盘机制)**       | **In-Memory Component Mutate (内存组件修改)**<br>LLM 产出结果后，调用特定组件的更新方法，修改 Python 字典或实体内部状态。                                                                            | **Atomic SQL Transaction (原子 SQL 事务)**<br>通过 `commitWorldStateWithEventInTransaction`，在单一事务内先给世界加行锁，递增序号，追加事件，更新状态，同生共死。            | Concordia 没有事务边界，某个组件修改中途崩溃会导致内存状态半死不活；镜界利用 PostgreSQL ACID 特性保证零脏数据。                                                       | **KEEP**: 提交边界必须由外层 DB 事务把关，禁止分散式就地修改。                                                  |
| **5. Event (事件模型)**              | **Natural Language String (自然语言叙事语句)**<br>事件仅仅是带有 `[event]` 前缀的文本段落（如 `[event] Alice paid Bob 10 dollars.`），供后续塞入 Context。                                           | **Structured Immutable Ledger (结构化不可变账本)**<br>具有全局唯一 UUID、World-Local Seq、强类型 Type、Actor/Target、JSON Payload、时间戳与关联 ID。物理禁止 UPDATE/DELETE。 | Concordia 的事件用于“让人类和 Agent 读故事”；镜界的事件用于“支撑审计、驱动状态机、多端同步与历史重放”。                                                               | **KEEP**: 坚持结构化 JSON Schema 与强类型事件流。                                                               |
| **6. LLM Dependency (大模型依赖度)** | **Hard Dependency (核心强依赖)**<br>没有 LLM，Concordia 的 Game Master 根本无法运行哪怕一个 Step（无法生成 Observation，无法 Resolve Action）。                                                      | **Zero Dependency (内核零依赖)**<br>World Kernel 内部完全不依赖任何大语言模型、SDK、API Key 或网络推理。核心世界是一个离线即可闭环的纯确定性状态机。                         | 镜界将 LLM 完全推到外层的 Agent 认知侧；核心物理、时间、经济系统对模型是完全“盲态”与解耦的。                                                                          | **KEEP**: 维持 World Kernel 零 AI 依赖原则，杜绝系统性雪崩风险。                                                |
| **7. Replay (回放能力)**             | **No Replay (无法真正回放)**<br>Concordia 仅能 Dump 最终的 HTML/JSON 日志展示发生了什么故事，无法通过事件流把系统恢复到过去的某一微秒并分叉执行。                                                    | **Event-Sourced Replay (事件溯源重放)**<br>理论上从初始 Seed 与 Checkpoint 出发，按 `world_seq` 顺序消费事件，可精准重构历史状态。                                           | 镜界为未来的调试、防作弊、离线推演和故事漫游保留了底层的数学可行性。                                                                                                  | **KEEP**: 保护事件账本的充足性，支撑后续 M2-T05 重放。                                                          |
| **8. Transaction (事务与并发)**      | **Single Thread Sequential Loop (单线程回合循环)**<br>默认通过 Turn-based 机制避免并发；遇到冲突全凭 LLM 在生成结果时自行调和。                                                                      | **Row-Locked Concurrent Ingress (基于行锁的并发接入)**<br>支持多 Agent 并发发起 ActionRequest，Kernel 通过 PostgreSQL 行锁排队裁决，配合乐观版本号检测并发冲突。             | 镜界的设计天然面向大规模网络并发服务；Concordia 仅面向单机离线 Batch 实验。                                                                                           | **KEEP**: 坚持行锁与明确的冲突错误码 (`KERNEL_CONFLICT`)。                                                      |
| **9. Scale (规模扩展上限)**          | **Ultra-Low Scale (极低规模，通常 5~20 实体)**<br>每次回合所有实体互相观察都需要调用 LLM 生成文本，Token 消耗呈 $O(N^2)$ 甚至更大爆炸，单步运行往往耗时数十秒。                                      | **Target 30 ~ 1,000+ (规划 LOD 分级支撑)**<br>单次校验在微秒至毫秒级（纯内存计算与单条 SQL 插入），MVP 30 居民可轻松维持 1Hz~60Hz 实时性。                                   | 架构决定了 Concordia 只能是实验室玩具或学术评测平台，绝对无法演进为 7×24 小时不间断运行的数字社会基座。                                                               | **KEEP**: 坚决抵制任何将高昂 Token 消耗嵌入世界基础设施的做法。                                                 |

## 镜界对 Concordia 的具体吸收与警惕总结

1. **唯一允许吸收的概念 (REFERENCE ONLY)**：
   - **Putative Event 提出机制**：Agent 永远只提出“假定动作”，世界经过仲裁后产出不可变“事实结果”。镜界现有的 `ActionRequest -> validateActionRequest -> world_events` 完全吸收并强化了这一哲学。
   - **组件化观察生成 (Observation per Actor)**：未来 M3/M7 在向居民同步世界动态时，应当根据居民所处空间网格（Spatial Cell）生成差异化观察切片，而不是无脑全图广播。
2. **严禁带入镜界的毒药**：
   - 用 Prompt 替代业务规则代码。
   - 用文本记忆代替关系型事实表与结构化账本。
   - 用 LLM 判定资产增减与扣费。
