# 13 - 开源技术复用分级与架构裁决建议 (Reuse Recommendations)

本文件严格遵循工程理性与克制原则，对开源技术进行**分级定性（REFERENCE / PORT / DEPENDENCY / DO NOT USE）**，并对镜界自有架构机制给出明确的**演进裁决（KEEP / ADJUST BEFORE M2 GATE / ADJUST LATER / REJECT EXTERNAL PATTERN）**。
坚决反对因外部项目不同就轻率推翻镜界既有 ADR，绝不提出“推倒重写 World Kernel”的非理性建议。

---

## 1. 外部开源组件复用分级清单

| 来源项目与模块                                      | 建议复用分级                        | 推荐理由与应用场景说明                                                                                                                             | 计划引入时机    |
| --------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| **AI Town: 异步操作状态机 (`inProgressOperation`)** | **REFERENCE (思想借鉴)**            | 极佳的异步长耗时任务与主模拟循环解耦模式。Agent 思考时打上挂起标记，完成后提交输入核验闭环。镜界可在 M3/M5 用自己的类型体系实现，无需依赖 Convex。 | M3 / M5         |
| **AI Town: 双层时间模型 (Step/Tick 批处理)**        | **REFERENCE (思想借鉴)**            | 在单个事务步（Step）内推进多个平滑微步（Tick），兼顾物理连续性与数据库提交效率。适合未来高频物理与低频事实提交的划分。                             | M3 / M7         |
| **AI Town: 对话文本与核心物理状态物理隔离**         | **REFERENCE (思想借鉴)**            | 文本流式存取，世界内核仅管理参与资格与物理距离。有效避免海量自然语言污染核心世界账本。                                                             | M3 / M4         |
| **AI Town: 全量活跃状态每秒反序列化加载**           | **DO NOT USE (坚决不用)**           | 将整个世界的所有实体每秒全量从数据库读进内存再全量比对 Diff，仅适合几十人玩具 Demo；上千人时瞬间引发内存与网络瘫痪。                               | 永久禁止        |
| **Concordia: Putative Event 假定事件提出机制**      | **REFERENCE (思想借鉴)**            | 实体永远只能提出假定动作（意图），必须由权威中介判定后才能成为事实。完全符合镜界 `ActionRequest != Event` 根原则。                                 | 当前已融入      |
| **Concordia: 基于 Prompt 的 LLM 权威裁决**          | **DO NOT USE (严厉禁止)**           | 让大模型在思维链中判定扣费、合法性与物品归属，存在严重的幻觉、越狱漏洞与不可审计性。镜界核心物理与资产必须纯代码确定性判定。                       | 永久禁止        |
| **Concordia: 生成式文本时钟 (GenerativeClock)**     | **DO NOT USE (坚决不用)**           | 由 LLM 脑补时间推进，无法支持严谨的物理与数字社会作息，破坏可重放性。                                                                              | 永久禁止        |
| **OpenClaw World: 10×10 Spatial Grid 与半径检索**   | **PORT (局部移植)**                 | 仅约 50 行纯 TypeScript 代码，无外部重型依赖。将平面划分为网格进行常量级视野查询，算法极其成熟小巧，适合直接吸收进镜界表现层。                     | M7 (Web 3D)     |
| **OpenClaw World: AOI 过滤的 WebSocket 广播**       | **PORT (局部移植)**                 | 根据视口半径裁切网络事件包，将全量广播优化为局部切片广播，大幅降低前端渲染与通信压力。                                                             | M7 (Web 3D)     |
| **OpenClaw World: 纯内存无事务 WorldState**         | **DO NOT USE (严厉禁止)**           | 坐标与状态仅保存在单进程 Node.js `Map` 中，服务重启即数据全丢。镜界定位为持久社会，必须以数据库为权威。                                            | 永久禁止        |
| **OpenClaw Core: Command Queue Lanes (通道分组)**   | **REFERENCE (思想借鉴)**            | 将命令按重要性划分为主干、系统、后台调度等多通道并赋予容量预算，防范后台任务饿死主干交互。适合 M5 网关设计。                                       | M5 (Agent 网关) |
| **Colyseus (官方框架，前置评估)**                   | **DEPENDENCY CANDIDATE (依赖候选)** | 成熟的权威房间与状态二进制增量同步框架，许可证为 MIT。适合在 M7 承担在线状态投影，不影响 PostgreSQL 事实主权。                                     | M7 Spike        |

## 2. 镜界自身架构机制裁决清单

| 镜界已有设计机制                         | 审查裁决结论                               | 事实依据与深度理由分析                                                                                                                                                                 |
| ---------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **World Kernel 唯一事实写入口**          | **KEEP (坚定保持)**                        | 本次研究的所有外部项目无论技术栈为何，凡是能够稳定运行的，均强制实行“修改必须穿透统一步骤”。镜界的 World Kernel 纯函数校验与单一事务写入口是防范多端并发污染的核心底线，必须绝对保持。 |
| **PostgreSQL 作为唯一持久事实源**        | **KEEP (坚定保持)**                        | OpenClaw World 纯内存运行在重启时丢失一切；AI Town 绑定私有 Convex 失去标准关系生态支持。PostgreSQL 16 的 ACID 事务、WAL 崩溃恢复、行级排他锁与丰富插件是镜界最坚硬的护城河。          |
| **ActionRequest ≠ Event**                | **KEEP (坚定保持)**                        | Concordia 与 AI Town 的共同经验证实：请求是主观期望（可能由于碰撞、断网、余额外泄而失败），事件是客观发生。混淆二者会导致重放发散与状态污染。                                          |
| **LLM 零权限（零事实裁决权）**           | **KEEP (坚定保持)**                        | Concordia 的教训明确警示：赋予 LLM 事实裁决权会摧毁系统的确定性与工业可靠性。镜界坚持 LLM 仅负责认知意图生成，事实判定 100% 走确定性算法代码。                                         |
| **固定 Seed 与确定性重放设计**           | **KEEP (坚定保持)**                        | 外部项目普遍缺乏确定性重放支持，导致其沦为无法严肃调试与长程推演的瞬态 Demo。镜界从一开始便在数据结构中绑定 `world.seed` 和单调连续序号，必须坚定不移地走下去。                        |
| **单世界单调连续自增序号 (`world_seq`)** | **KEEP (坚定保持)**                        | 数据库 Trigger 物理拦截跳序与删除，为事件溯源提供了不可撼动的数学全序保证。                                                                                                            |
| **M2-T04 Event Ledger 表结构**           | **KEEP (坚定保持)**                        | 经审查已完整具备类型、序号、时间戳、JSONB Payload、Schema 版本号与关联 ID，完全能满足后续 M2-T05 重放与 Checkpoint 需求。                                                              |
| **M2 Gate 前是否需要回退或修改代码**     | **KEEP (保持不动，无阻断修复)**            | 当前没有发现任何阻断 M2 Gate 的 P0 级缺陷。已有代码质量与测试覆盖完备，不应在 Gate 前做非必要的代码扰动。                                                                              |
| **ActionRequest 幂等结果返回增强**       | **ADJUST LATER (未来调整，Before M3)**     | 当前重复请求仅返回拒绝错误码，无法取回既往执行结果。由于 M2 尚未实现 Action API 与 ActionResult，此项调整应放在 M3 构建动作执行闭环时处理。                                            |
| **事件账本 `causation_id` 补充**         | **ADJUST LATER (未来调整，Before M6)**     | 目前单步事件无需级联溯源，待经济系统涉及多步派生交易时再行扩充数据库列。                                                                                                               |
| **领域事件 Payload 强类型契约**          | **ADJUST LATER (未来调整，Before M2-T05)** | 在落地 Checkpoint 与 Replay 时，为具体领域事件 Payload 增加细粒度 Zod 检查。                                                                                                           |
| **采用外部项目的全量内存状态加载**       | **REJECT EXTERNAL PATTERN (彻底拒绝)**     | 坚决拒绝 AI Town 的每秒全表载入内存模式，镜界坚持数据库按需加载与空间分片。                                                                                                            |
| **采用外部项目的 LLM 时钟推断**          | **REJECT EXTERNAL PATTERN (彻底拒绝)**     | 坚决拒绝 Concordia 的 Generative Clock，镜界坚持基于物理锚点与受控步长的 World Clock。                                                                                                 |
