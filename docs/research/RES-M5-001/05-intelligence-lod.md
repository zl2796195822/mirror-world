# 05 - 智能细节层次体系 (Intelligence LOD Architecture)

## 1. 为什么持久数字社会必须有 Intelligence LOD？

在计算机图形学（3D Graphics）中，距离摄像机 100 米外的远景树木只渲染 20 个顶点的低模，距离摄像机 1 米处的近景树木才渲染上万面的高模与次时代贴图，这就是几何细节层次（Geometric LOD）。

同理，在一个拥有成百上千名居民的持久数字社会中：

- 远处街区、人类玩家看不见的居民；
- 正在房间里睡觉或在流水线上螺丝的工人；
- 与当前主线冲突毫无瓜葛的背景路人；

**绝对不能、也完全没有必要与正在和玩家唇枪舌剑的议员或处于破产悬崖边缘的主角消耗相同的 AI 计算预算！**

镜界首次正式确立**智能细节层次（Intelligence Level of Detail, 简称 I-LOD）**体系，作为运行时算力动态配额与降级调度的核心中枢。

## 2. 四级智能细节层次定义 (I-LOD Hierarchy)

```text
┌────────────────────────────────────────────────────────────────────────┐
│ LOD-I3: FULL MODEL COGNITIVE DEPTH (深层认知 - 前沿旗舰大模型)          │
│ - 适用: 玩家焦点主角、重大伦理冲突、高阶商业博弈                        │
│ - 特征: 完整多轮记忆召回、深度心理推理、自然语言长文本生成               │
├────────────────────────────────────────────────────────────────────────┤
│ LOD-I2: LIGHT MODEL / OCCASIONAL (敏捷认知 - 轻量小模型/端侧SLM)       │
│ - 适用: 视口内次要居民、偶发社会闲聊、突发简单环境变动反应              │
│ - 特征: 简要记忆检索、单步意图分类与抽取、短句对话生成                  │
├────────────────────────────────────────────────────────────────────────┤
│ LOD-I1: RULE-HEURISTIC & CACHED (启发式规则与缓存计划 - 零大模型)      │
│ - 适用: 中远景居民、熟悉路线通行、结构化工作、日常商业采购              │
│ - 特征: 基于行为树 (Behavior Tree)、效用矩阵、缓存历史计划, 毫秒级计算   │
├────────────────────────────────────────────────────────────────────────┤
│ LOD-I0: DORMANT / DETERMINISTIC ONLY (休眠静息态 - 纯确定性生命基线)    │
│ - 适用: 睡眠中居民、离线静止居民、视口之外背景人口                      │
│ - 特征: 仅靠 M3 Life Engine 状态机步进生理时间, 零网络IO, 纯内存运算    │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. I-LOD 动态评估因子与数学裁决模型

系统不需要每秒为全界所有居民重算 LOD，而是在**居民触发唤醒（Agent Wake Request）**时，由 `IntelligenceLODArbiter` 执行纯函数动态求值：

$$\text{Score} = w_1 \cdot P_{\text{user}} + w_2 \cdot I_{\text{event}} + w_3 \cdot R_{\text{rel}} + w_4 \cdot A_{\text{goal}} + w_5 \cdot S_{\text{social}} + w_6 \cdot T_{\text{tier}} - w_7 \cdot B_{\text{pressure}}$$

### 3.1 核心输入因子定义与量化标准：

1. **玩家邻近度 ($P_{\text{user}} \in [0, 100]$)**：
   - 0 米（正与玩家对话）：100 分；
   - 5 米以内（玩家视口核心区）：70 分；
   - 20 米以内（同街区但非直接视野）：30 分；
   - 20 米外（不在任何在线玩家同屏视野）：0 分。
2. **事件冲击度 ($I_{\text{event}} \in [0, 100]$)**：
   - 遭遇破产、失窃、被捕、关键抉择：100 分；
   - 收到大额订单、朋友邀请聚餐：50 分；
   - 正常路过、物品微小打折：10 分；
   - 日常生理循环：0 分。
3. **关系相关度 ($R_{\text{rel}} \in [0, 100]$)**：
   - 交互对象是挚友、死敌、配偶或直属雇主：80~100 分；
   - 交互对象是普通熟人：30 分；
   - 交互对象是路人陌生人：0 分。
4. **目标歧义性 ($A_{\text{goal}} \in [0, 100]$)**：
   - 前序动作遭遇内核冲突（`KERNEL_CONFLICT`），原有计划完全失效需要重新思考：80 分；
   - 当前作息目标单一明确（如“走去工作地点打卡”）：0 分。
5. **居民社会层级 ($T_{\text{tier}} \in [0, 100]$)**：
   - 数字社会核心主角、市长、银行家：60~100 分底分加权；
   - 普通市民背景人口：0 分。
6. **全局系统预算压力 ($B_{\text{pressure}} \in [0, 100]$)**：
   - 当前 Token 消耗接近本小时预算红线，或队列出现背压排队时，$B_{\text{pressure}}$ 飙升，自动强制向下压制高档 LOD。

### 3.2 最终求值分级映射规则：

- **$\text{Score} \ge 80$** $\implies$ **`LOD-I3` (前沿全模深思)**；
- **$50 \le \text{Score} < 80$** $\implies$ **`LOD-I2` (轻量敏捷推理)**；
- **$20 \le \text{Score} < 50$** $\implies$ **`LOD-I1` (规则决策与缓存计划)**；
- **$\text{Score} < 20$** $\implies$ **`LOD-I0` (直接休眠，由 Life Engine 规则推进)**。

## 4. 算力动态降级与熔断机制

为了防止不可预测的突发流量（例如 50 名居民在广场同时遭遇突发事件）引发系统雪崩，I-LOD 体系配备了**自动防御熔断器**：

1. **硬并发阈值拦截 (Hard Concurrency Cap)**：
   - 全局限制 `LOD-I3` 并发任务数最高为 $K_{\text{max}}$（如 10 个）。超过阈值的任务自动降级为 `LOD-I2` 处理。
2. **渐进式优雅劣化 (Graceful Degradation Curve)**：
   - 当 API 提供商响应延迟超过 5 秒时，系统自动临时将全局门槛提高 20 分，使更多边缘居民快速退回 `LOD-I1` 规则层，确保前端玩家交互的绝对流畅。
