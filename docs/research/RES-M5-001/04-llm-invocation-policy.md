# 04 - 大模型调用策略与场景分类矩阵 (LLM Invocation Policy)

## 1. 核心架构哲学：大模型不是日常生理引擎

在镜界设计中，一个最核心的认知突破是：

> **大模型（LLM）是居民的“高阶前额叶皮层（Higher Cognitive Cortices）”，而不是驱动心跳、呼吸与肌肉反射的“脑干（Brainstem）”。**

在 M3 里程碑中，**确定性生命引擎（Life Engine）**已经通过效用函数（Utility AI）、状态机和计划表，完美、高速、零成本地解决了居民的生理与社会作息基准：

- 何时去卫生间；
- 饥饿时走向冰箱或街区食堂吃快餐；
- 困倦时上床睡觉；
- 准点打卡上下班并结算基础轮班薪资；
- 路上与熟人打照面时点头示意。

如果居民“每走一步路”、“每吃一口饭”、“每买一瓶水”都要向云端大模型发送一个 HTTP 请求，系统不仅每秒要支付数十美元的无效账单，而且居民会因为网络延迟频繁在大街上“发呆卡顿”数秒。

## 2. LLM 调用三级分类法则 (The Three-Tier Invocation Taxonomy)

根据决策的不确定性、社会影响度与语言生成需求，系统将居民的一切行为划分为三大类别：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. NO_LLM (零模型确定性行为 - 占比 85% ~ 95%)                           │
│    - 由 M3 Life Engine 规则与状态机直接消化, 耗时 < 1ms, 成本 $0.000000 │
├────────────────────────────────────────────────────────────────────────┤
│ 2. OPTIONAL_LLM (可选模型增强行为 - 占比 4% ~ 12%)                      │
│    - 由本地小模型 (SLM) 或提示模板生成; 当算力吃紧或处于远景时自动降级  │
├────────────────────────────────────────────────────────────────────────┤
│ 3. REQUIRED_LLM (必须调用前沿模型 - 占比 1% ~ 3%)                       │
│    - 重大社会冲突、玩家交互、颠覆性人生规划; 必须调用 Tier-2/3 高阶大模型│
└────────────────────────────────────────────────────────────────────────┘
```

## 3. 详细场景分类与决策仲裁矩阵

| 行为类别         | 典型具体行为场景                                  | 判定标准与触发机制                           | 选用模型级别                                       | 降级兜底方案 (Fallback)                             |
| :--------------- | :------------------------------------------------ | :------------------------------------------- | :------------------------------------------------- | :-------------------------------------------------- |
| **NO_LLM**       | **日常生理排解** (睡觉、醒来、如厕)               | 生理需求槽值超过阈值 (如 Fatigue > 80)       | **无 (纯代码)**                                    | 不适用 (自身即为最高效实现)                         |
| **NO_LLM**       | **例行通勤与工作** (通勤打卡、轮班打工)           | 依据预设日程表 (Work Schedule) 的定时触发    | **无 (纯代码)**                                    | 直接生成 `WORK` / `MOVE` ActionRequest              |
| **NO_LLM**       | **基础日常采购** (便利店买便当/面包)              | 依据常备消耗品清单与最低资金安全线判定       | **无 (纯代码)**                                    | 自动选购满足饥饿且最便宜的合法 Food 物品            |
| **NO_LLM**       | **擦肩而过的礼貌寒暄** (点头打招呼)               | 两熟人在同一网格相遇，但当前各自主线任务繁忙 | **无 (预设文本库)**                                | 从居民性格动作库随机抽取预设表情/动作               |
| **NO_LLM**       | **冲突重试后的路径避让** (物理撞人/堵路)          | 前序 `MOVE` 遇到 `KERNEL_INVALID_LOCATION`   | **无 (纯 A\* 避障)**                               | 空间网格就近选择候选空闲坐标步进                    |
| **OPTIONAL_LLM** | **日常小店闲聊与天气抱怨**                        | 两人在咖啡馆空闲等待，且亲密度 > 30          | Tier-1 (8B 级别 SLM 或 Flash-Lite)                 | 使用基于关系标签的槽位插值模板文本                  |
| **OPTIONAL_LLM** | **轻微偶发事件反应** (下雨没带伞、商品微调涨价)   | 环境状态突变，需要居民展现情绪表情或微动作   | Tier-1 (轻量模型)                                  | 触发内置的负向情绪状态，按规则就近避雨              |
| **OPTIONAL_LLM** | **日常日记简报生成** (睡前记录)                   | 居民入睡时触发，对一天发生的事情做总结       | Tier-1 (后台离线批处理)                            | 跳过日记，或直接按事件流水拼接摘要                  |
| **REQUIRED_LLM** | **人类玩家主动发起交互**                          | 玩家点击居民并发起自然语言输入或提议         | Tier-3 (前沿多轮大模型，如 Claude Sonnet / GPT-4o) | 提示“对方正在沉思...”，若超时返回委婉礼貌的客套话   |
| **REQUIRED_LLM** | **突发恶性社会危机** (遭遇盗窃、破产、失业裁员)   | 自身资源或核心资产发生剧烈负向跃迁           | Tier-2/3 (深度推理模型)                            | 触发悲伤/愤怒硬规则，先进入 `WANDER` 迷茫或回家锁门 |
| **REQUIRED_LLM** | **重大商业谈判与大额契约** (租房合租、合伙做生意) | 涉及金额超过自身流动资产的 30%               | Tier-2/3 (强逻辑结构化模型)                        | 拒绝交易：“我需要认真考虑，暂时不能答应”            |
| **REQUIRED_LLM** | **深层社交冲突与伦理抉择** (揭发背叛、表白示爱)   | 关系矛盾度 (Conflict) > 80 或好感度达到峰值  | Tier-3 (复杂人设心智模型)                          | 暂时保持沉默或回避接触                              |

## 4. 特别裁决：TALK 动作绝不等于全量调用大模型

在以往很多系统设计中，经常出现致命代码假设：

```typescript
// 错误反模式：将 TALK 与 LLM 强行绑定
if (action.type === "TALK") {
  await callFrontierLLM(prompt); // 灾难！
}
```

在镜界中，**严正声明：TALK 动作不等于必须调用昂贵大模型！**

1. **机械性日常交互 TALK 走预设模板或 NO_LLM**：
   - 比如：“老板，结账”、“一份便当，谢谢”、“借过一下”。这类对话占社会交互的 80% 以上，直接由领域规则和插值模板库输出，无需经过任何模型。
2. **非关键 NPC 间的对话使用 SLM 或异步离线生成**：
   - 两个普通背景居民聊今天的天气或物价，由本地部署的轻量小型模型（如 4B~8B 参数）生成 10~20 个 Token 的简短问候即可。
3. **只有当且仅当满足下列条件时，TALK 才升级为高阶 LLM 调用**：
   - **条件 A**：对话参与方至少一方是真实人类玩家（`HUMAN` 或 `PROXY`）；
   - **条件 B**：对话涉及关键剧情道具交换、重大债务借贷或法律协议订立；
   - **条件 C**：两位主角居民处于重大叙事冲突的关键转折点，且两者的 `Intelligence LOD` 均处于最高等级（`LOD-I3`）。
