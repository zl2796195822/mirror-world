# 31 - 架构开放性问题与后续跟踪清单 (Open Questions)

## 1. 遗留前瞻性架构问题清单

本文件记录在本次 RES-M5-001 研究中识别出的长线演进问题。这些问题不阻断本次研究的结论闭环，但需要在进入 M3 Action Loop、M4 记忆落地或正式 M5 实施前持续跟踪并立项处理。

---

### OQ-M5-001: Pre-M3 数据库 Schema 升级与 KernelActionOutcome 落地时机

- **问题描述**:
  - `action_requests` 表目前仅支持请求行插入与基于指纹的 `duplicate` 检测，缺少 `status`、`reason_code`、`committed_event_id` 与 `result_payload` 字段。
- **影响范围**:
  - 直接影响 M3 生命引擎真实 Action Loop 与 M5 认知重规划的因果闭环。
- **推荐解决路径**:
  - 在正式 M3-T02（或 Pre-M3 专项）中创建数据库 Migration，为 `action_requests` 增加上述字段，并升级 `persistValidatedActionRequest` 实现真正的执行结果回写。

---

### OQ-M5-002: 多居民同场对话中的“轮次协调锁”与插话机制 (Conversation Turn Taking)

- **问题描述**:
  - 当三位居民在同一家咖啡馆聚集并发起群聊时，如何防止三人的 Agent Runtime 同时唤醒并在同一秒提交说话意图（打架争抢发言）？
- **借鉴方案**:
  - AI Town 采用在世界表中打上 `conversation.isTyping` 标记；OpenClaw 采用 Per-channel 队列。
- **推荐解决路径**:
  - 在 M5 对话设计中，引入轻量级“发言权令牌（Turn Token）”，持有令牌者方可唤醒大模型生成回复，其他在场者暂时转入倾听观察态。

---

### OQ-M5-003: 离线批量记忆反思对世界时钟的因果依赖 (Offline Reflection vs World Time)

- **问题描述**:
  - 居民在夜晚睡眠（`LOD-I0`）时，后台离线车道（`LANE_BACKGROUND_SUMMARY`）将调用大模型进行一天的记忆总结与反思提炼。此时若用户快进世界时钟（如 10x 速度推演），后台批处理可能落后于世界虚拟时间。
- **推荐解决路径**:
  - 记忆提炼任务携带所属的虚拟自然日日期（如 `worldDate = "2026-09-08"`）。无论物理推演多快，批处理任务按历史事件批次幂等消费，提炼出的记忆标记为过去的发生时间，不产生因果倒流。

---

### OQ-M5-004: 生产环境下本地开源模型（vLLM / Ollama）的物理部署拓扑

- **问题描述**:
  - 虽然本研究在架构上设计了云端商业模型与本地开源小模型（如 Qwen2.5-7B）的无缝热切，但在未来正式上云时，本地推理节点（GPU 实例）是与 Web 服务混部还是独立为专属微服务？
- **推荐解决路径**:
  - 初期开发与测试阶段：直接调用云端轻量极速模型（如 Gemini Flash Lite，单价极低且免除 GPU 运维负担）；
  - 商业私有化部署阶段：独立搭建 vLLM 兼容 OpenAI 标准端点的推理网关，通过配置平滑切换。

---

### OQ-M5-005: 恶意玩家通过长时间长文本诱导居民导致 Token 耗尽攻击 (Denial of Wallet)

- **问题描述**:
  - 若人类玩家恶意编写极其复杂的长篇绕口令或长篇小说持续向某个居民发送，试图消耗服务器的 API 预算。
- **推荐解决路径**:
  - 玩家交互通道设立**单玩家单日交互限额（Player Interaction Quota）**；
  - 玩家发送给居民的对白文本在进入网关时强制按 200 字硬截断，超长文本直接丢弃多余部分，从根源上防御钱包耗尽攻击（Denial of Wallet Attack）。
