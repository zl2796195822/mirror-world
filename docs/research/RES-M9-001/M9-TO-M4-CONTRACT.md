# M9 → M4 Contract

## Boundary

M9 owns identity link, control/delegation authority and attribution metadata. M4 owns resident-scoped Memory/Relationship/Perception projections. Neither may overwrite the other’s authority.

## M4 may receive

- stable `residentId` and `worldId`;
- world action/event refs plus control-origin lineage when a proxy action committed;
- bounded identity/public display projection according to privacy policy;
- consent/provenance references only when required for a memory/representation purpose.

## M4 must not receive by default

- raw auth identity, session cookie, email/phone/real ID;
- raw/derived biometric data;
- full Proxy Charter or private budget;
- another resident’s private memory or relationship state;
- hidden prompt/CoT.

## Proxy interaction

`Proxy action → committed world interaction → M4 perception eligibility → resident memory/relationship projection`。M4 must preserve source lineage and may distinguish resident world actor from control source; proxy status does not erase the interaction.

M4’s `World Event ≠ Observation ≠ Memory` and `World Fact ≠ Resident Belief` invariants remain authoritative. M9 does not implement M4 ports or memory tables.
